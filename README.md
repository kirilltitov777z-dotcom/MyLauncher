# MyLauncher

Лаунчер, который я собрал из двух открытых проектов и выложил как один репозиторий.

## Кто что сделал (важно, кредиты сохранены намеренно)

- **Объединение, бренд и поддержка репозитория — я.** Я соединил два проекта в одну сборку и настроил автоматическую сборку APK через GitHub Actions.
- **Основа, исходный код (Kotlin + Jetpack Compose) — [kotlalipopus](https://github.com/kotlalipopus), проект [Expressive-launcher](https://github.com/kotlalipopus/Expressive-launcher).** Лицензия MIT, полный текст в [LICENSE](LICENSE). Оригинальный README сохранён в [README.upstream.md](README.upstream.md).
- **Готовый APK ColorOS 17 — [h21975340-creator](https://github.com/h21975340-creator), проект [Color-os-17-launcher](https://github.com/h21975340-creator/Color-os-17-launcher).** В описании того репозитория указано, что основа взята у **kyyrick_tech** (TikTok). Лицензия у этого APK не указана, поэтому он лежит отдельным файлом в `prebuilt/` и не смешивается с исходником MIT.

Я не удалял упоминания авторов: лицензия MIT прямо требует сохранять copyright-уведомление, а чужой переупакованный APK тем более нельзя выдавать за свой.

## Что внутри

- `app/`, `gradle/`, `build.gradle.kts` и т.д. — собираемый из исходников лаунчер (Expressive Launcher).
- **Свой экран блокировки в стиле ColorOS** — новая часть, добавленная в этом репозитории:
  - часы: 3 готовых стиля (ColorOS, классика, стекло) + свой акцентный цвет и секунды;
  - фейковый отпечаток с анимацией сканирования — по нажатию открывает камеру (можно сделать фото);
  - фон — размытые обои телефона;
  - появляется **после системной блокировки** (событие `USER_PRESENT`): сначала системный экран телефона, потом наш;
  - свайп вверх или стрелка — вернуться на рабочий стол.
  - Настраивается в Настройки → Поведение → Экран блокировки. Отпечаток декоративный, это не биометрия и не обход блокировки.
- `prebuilt/ColorOS17Launcher-5.0-parallel-close-1.apk` — готовый APK ColorOS 17, просто файл.
- `.github/workflows/build.yml` — GitHub Actions: собирает release-APK и публикует оба APK в Release.

## Сборка

### Через GitHub Actions (основной способ)

1. Создай пустой репозиторий на GitHub.
2. Залей сюда все файлы (можно архивом через веб-интерфейс или `git push`).
3. Открой вкладку **Actions** → разреши workflows → дождись завершения **`Build launchers`**.
4. Готовые APK будут во вкладке **Releases** (и в артефактах сборки).

Workflow собирает `assembleRelease`. Подпись — уже настроенным в проекте debug-ключом, поэтому отдельные секреты для подписи не нужны, APK ставится на телефон сразу.

### Локально

Нужны JDK 17 и Android SDK (платформы 36/37).

```sh
./gradlew assembleRelease
```

APK появится в `app/build/outputs/apk/release/`.

## Если хочешь своё имя в приложении

В `app/src/main/res/values/strings.xml` поменяй значение `app_name`. Пакет (`applicationId`) меняется в `app/build.gradle.kts` — но если сменить его, приложение станет отдельным и не обновит уже установленную версию.

Подробности про возможности лаунчера и разрешения — в [README.upstream.md](README.upstream.md).
